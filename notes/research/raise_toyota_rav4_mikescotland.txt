1. SPEED & AVERAGE SPEED 
 
speed value is encoded in 0.01 km/h units as a 16-bit unsigned integer, split into two bytes 
(LSB first).  
 
Byte Index Purpose Value / Formula 
0 Header 0x2E (fixed start byte) 
1 Command 0x7D (CMD_MULTI_FUNCTION) 
2 Length 0x05 (5 bytes of payload) 
3 Sub-command 0x03 (indicates speed payload) 
4–5 Speed 
speed_raw = uint16_t(speed_kmh × 100) → LSB 
first 
6–7 Average Speed avg_raw = uint16_t(avg_kmh × 100) → LSB first 
8 Checksum checksum = (cmd + len + ∑payload) ^ 0xFF 
 
Full Formula (C-Style) 
 
uint16_t speed_raw = (uint16_t)(speed_kmh * 100.0f); 
uint16_t avg_raw   = (uint16_t)(avg_kmh * 100.0f); 
 
uint8_t payload[5] = { 
  0x03, 
  uint8_t(speed_raw & 0xFF),      // speed LSB 
  uint8_t(speed_raw >> 8),        // speed MSB 
  uint8_t(avg_raw & 0xFF),        // avg speed LSB 
  uint8_t(avg_raw >> 8)           // avg speed MSB 
}; 
 
uint8_t checksum = CMD_MULTI_FUNCTION + 5; 
for (uint8_t i = 0; i < 5; ++i) checksum += payload[i]; 
checksum ^= 0xFF; 
 
 
 
 
 
 
 
 
Example: Speed = 123.45 km/h, Avg = 200.00 km/h

Byte Index Purpose Value / Formula

checksum ^= 0xFF;

3. LIGHTS 
Byte Index Purpose Value / Formula 
0 Header 0x2E (fixed start byte) 
1 Command 0x7D (CMD_MULTI_FUNCTION) 
2 Length 0x02 (2 bytes of payload) 
3 Sub-command 0x01 (indicates lights payload) 
4 Lights bitmask lightMask = bitwise OR of active light states 
5 Checksum checksum = (cmd + len + subcmd + bitmask) ^ 0xFF 
 
Full Formula C Style 
uint8_t subcmd     = 0x01; 
uint8_t lightMask  = 0x00; 
 
// Bitwise composition based on active states: 
if (rightActive)     lightMask |= 0x08; 
if (leftActive)      lightMask |= 0x10; 
if (highBeamsOn)     lightMask |= 0x20; 
if (headlightsOn)    lightMask |= 0x40; 
if (parkingLightsOn) lightMask |= 0x80; 
 
uint8_t checksum = CMD_MULTI_FUNCTION + 2 + subcmd + lightMask; 
checksum ^= 0xFF; 
 
Example: Headlights + Parking + Left Indicator 
• Bitmask = 0x40 | 0x80 | 0x10 = 0xD0 
• Payload = 01 D0 
Final UART frame: 2E 7D 02 01 D0 AF

4. DOORS 
 
Byte Index Purpose Value / Formula 
0 Header 0x2E (fixed start byte) 
1 Command 0x24 (CMD_DOOR_STA TUS) 
2 Length 0x01 (1 byte of payload) 
3 Door bitmask Bitwise OR of active door states 
4 Checksum 
checksum = (0x24 + 0x01 + doorMask) ^ 
0xFF 
 
Full Formula C Style 
uint8_t doorMask = 0; 
 
// Bitwise composition based on CAN status bits: 
if (status & (1UL << 20)) doorMask |= 0x80; // Driver (UK right front) door 
if (status & (1UL << 19)) doorMask |= 0x40; // Passenger (UK left front) door 
if (status & (1UL << 23)) doorMask |= 0x08; // Boot 
if (status & (1UL << 21)) doorMask |= 0x10; // Rear left (confirmed) 
if (status & (1UL << 22)) doorMask |= 0x20; // Rear right (confirmed) 
 
uint8_t checksum = 0x24 + 0x01 + doorMask; 
checksum ^= 0xFF; 
 
Example: Rear Left + Passenger Open 
• Bitmask = 0x10 | 0x40 = 0x50 
Final UART frame: 2E 24 01 50 8A 
 
5. STEERING WHEEL ANGLE 
  Angle is encoded as a signed 16-bit integer in 0.1° units, LSB first. 

===== PAGE 5 =====
  Negative angles use two’s complement representation. 
 
Byte Index Purpose Value / Formula 
0 Header 0x2E 
1 Command 0x29 
2 Length 0x02 (2 bytes of payload) 
3–4 Payload Signed 16-bit angle in 0.1° units, LSB first 
5 Checksum (0x29 + 0x02 + payload[0] + payload[1]) ^ 0xFF 
 
Full formula C Style 
int16_t rawAngle = int16_t(angle_deg * 10.0f); // angle in 0.1° units 
 
uint8_t payload[2] = { 
  uint8_t(rawAngle & 0xFF),      // LSB 
  uint8_t(rawAngle >> 8)         // MSB 
}; 
 
uint8_t sum = 0x29 + 0x02 + payload[0] + payload[1]; 
uint8_t checksum = sum ^ 0xFF; 
 
Example: –26.0° 
• –26 × 10 = –260 → 0xFFE6 (two’s complement) 
• Payload: E6 FF 
• Sum: 0x29 + 0x02 + 0xE6 + 0xFF = 0x210 
• Lower byte: 0x10 
• Checksum: 0x10 ^ 0xFF = 0xEF 
Final UART frame: 2E 29 02 E6 FF EF 
Steering wheel angle is -540 to 540 – values from the Canbus should be mapped to these 
values. You can experiment with these values, Clio III has best accuracy with -500 to 500

6. OUTSIDE TEMPERATURE 
Byte Index Purpose Value / Formula 
0 Header 0x2E 
1 Command 0x28 
2 Length 0x0C (12 bytes of payload) 
3–14 Payload All 0x00 except index 5 
5 Encoded Temp (temp_celsius + 40) × 2 
15 Checksum (0x28 + 0x0C + ∑payload[0..11]) ^ 0xFF 
 
Encoding formula 
// Step 1: Encode temperature 
uint8_t encoded_temp = (int8_t(temp_celsius) + 40) * 2; 
 
// Step 2: Insert into payload 
payload[5] = encoded_temp; 
 
// Step 3: Calculate checksum 
uint8_t sum = 0x28 + 0x0C; 
for (int i = 0; i < 12; ++i) sum += payload[i]; 
uint8_t checksum = sum ^ 0xFF; 
 
Example: 21°C 
• Encoding: (21 + 40) × 2 = 122 → 0x7A 
• Payload: 00 00 00 00 00 7A 00 00 00 00 00 00 
Final frame: 2E 28 0C 00 00 00 00 00 7A 00 00 00 00 00 00 51

Battery & Status (Byte 3) 
This byte contains two pieces of information: 
• Bit 7: Hybrid Vehicle Indicator. A value of  
1 confirms the vehicle is a hybrid model. 
• Bits 6-0: Battery Level. Represents the battery charge level, where the original 
vehicle has 8 bars of display. 
 
Energy Flow Bitmask (Byte 4) 
This byte describes the power flow by setting individual bits for each active path. Multiple 
bits can be set to 1 at the same time. 
• Bit 0: Motor is charging the Battery. 
• Bit 1: Motor is driving the Wheels. 
• Bit 2: Engine is driving the Motor . 
• Bit 3: Engine is driving the Wheels. 
• Bit 4: Battery is driving the Motor. 
• Bit 5: Wheels are driving the Motor (regenerative braking). 
 
Example: Engine Drive & Charge 
Let's assume a scenario where the engine is driving the wheels and simultaneously charging 
the battery via the motor . The battery level is 6 out of 8. 
1. Constructing the Battery & Status Byte (Byte 3) 
• Bit 7 (Is Hybrid) = 1. 
• Bits 6-0 (Level 6) = 0000110. 
• The resulting byte is 10000110 in binary, which is $0x86. 
2. Constructing the Energy Flow Bitmask (Byte 4) 
• Engine → Wheels is active, so we set  
Bit 3 (00001000). 
• Engine → Motor is active, so we set  
Bit 2 (00000100). 
• Motor → Battery is active, so we set  

===== PAGE 10 =====
Bit 0 (00000001). 
• The combined bitmask (bitwise OR) is 00001101 in binary, which is $0x0D. 
3. Final UART Frame The complete frame for this example would be: 2E 1F 02 86 0D 4B

This byte is a bitmask that controls the interpretation of the entire message.

• Bit 6: Alarm Status. A value of

• Bit 2: Display Style. 0 displays tires in a simple row;

• Bits 1-0: Unit of Measurement. These bits select the unit for the pressure bytes:

Pressure Encoding Logic 
The pressure for each tire is sent as a single byte. The raw byte value is multiplied by the unit 
selected in the Status Byte to get the final reading. 
A special value of  
0xFF indicates that the pressure data for that specific tire has not been received or is invalid. 
Example: Pressures in PSI 
Let's assume the following conditions: 
• Status: TPMS is present, no alarm, spare tire should be shown, car layout display is

10. REMAINING RANGE 
Frame Layout • Header (0x2E) • Cmd = 0x21 • Len = 0x07 • Payload: 
• bytes 3–6 → padding (always 0x00) 
• byte 7 → MSB of range 
• byte 8 → LSB of range 
• byte 9 → constant pad (0x02) • Checksum = (cmd + len + sum(payload)) ^ 0xFF 
Formula C Style 
uint16_t range_km = (uint16_t(frame[7]) << 8) 
                  | uint16_t(frame[8]); 
• e.g. sending … 02 1C 02 … ➔ MSB=0x02, LSB=0x1C yields 0x021C = 540 km

C-STYLE CALCULATION PROCEDURE 
To obtain the display value for fuel consumption, the following procedure must be used. 
(a) Combine Data1 (high byte) and Data2 (low byte) into a single 16-bit unsigned integer . 
// uint8_t data1, data2; uint16_t rawValue = (data1 << 8) | data2; 
(b) Convert the resulting 16-bit integer to a floating-point value and divide by 10.0. 
// float finalValue; finalValue = (float)rawValue / 10.0f; 
 
Example: 
The value to be displayed on the head unit is 6.5 L/100KM. 
Identify Data Bytes: 
• Data0 = 0x02 (Unit is L/100KM) 
• Data1 = 0x00 
• Data2 = 0x41 
Combine Bytes (Step a): 
• rawValue = (0x00 << 8) | 0x41; 
• rawValue is now 0x0041. 
Calculate Final Value (Step b): 
• The decimal equivalent of 0x41 is 65. 
• finalValue = 65 / 10.0f; 
• finalValue is now 6.5 
FINAL FRAME: 2e 22 03 02 00 41 97
